Fill a workspace created with example content: three projects, twenty-five issues across the board,
labels, components, a version, a milestone and four cycles.

Written through the module's own services rather than as inserts, so the issues have keys from the
project counter, ranks, the template's workflow and the status history the cycle report reads. Two
things it cost a run to learn, both recorded in the file: `StatusCategory` is
`backlog | todo | in_progress | done | cancelled | triage` and an invented name moves nothing while
reporting success, and the support project uses the `simple` template because the `support` one
installs a workspace-level `impact` field marked required — which then refuses every issue in every
other project in the workspace.
